# Study Notes: Getting Started

This is a sample notes page showing how each topic file in this repo can be laid out.

## Topic template

Each topic note follows the same layout:

1. **Summary**: two or three sentences in my own words.
2. **Key ideas**: the points I must remember.
3. **Example**: a small, concrete scenario.
4. **Common mistakes**: traps to avoid on the exam.
5. **Self-check**: questions to answer without looking.

## Sample: Prompt design basics

**Summary**
A good prompt states the task clearly, gives the context the model needs, and says what a good answer looks like.

**Key ideas**
- Be specific about the goal and the output format.
- Give examples when the format matters.
- Separate instructions from the data being processed.

**Example**
Instead of _"Summarise this"_, write _"Summarise this support ticket in three bullet points: the problem, what the customer tried, and what they want."_

**Common mistakes**
- Vague instructions that leave the model guessing.
- Mixing instructions and input text with no clear boundary.

**Self-check**
- [ ] Can I explain why examples improve output consistency?
- [ ] Can I rewrite a vague prompt into a specific one?
